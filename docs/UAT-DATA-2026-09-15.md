## ผลตรวจข้อมูล

- Seed ซ้ำแล้วไม่เพิ่มข้อมูล ตรวจผ่านด้วย audit batch เดิม
- ยอดกันยายนของบัญชีส่วนตัว 35000/5300 ตรงชุดข้อมูล
- สมาชิกบัญชีผู้ดูแลเข้าถึงบัญชี UAT ทั้ง4ได้
- ไม่มี recurring UAT สถานะ active
- ดาวน์โหลดภาพ/PDF/WAV จาก production ได้ HTTP200 และ MIME type ถูกต้อง

## ยังไม่ใช่ผลผ่าน UAT

ข้อมูลจำลองที่สร้างไม่ใช่หลักฐานว่าบริการ OCR/STT/PDF/cron ทำงานจริง ต้องส่งไฟล์และเสียงพูดจริงเพื่อทดสอบปลายทางครบก่อน sign-off

- ข้อกำหนด Pro20 / Pro Max100 ยังไม่ตรงโค้ด `recurringLimit.ts` ที่จำกัด20ทุกแพ็กเกจ: OPEN
- กลุ่มนี้ใช้รหัส UAT จำลอง ไม่มีการสร้างกลุ่ม LINE จริง; การแท็ก ส่งข้อความ และสิทธิ์ผู้ใช้จริงยังต้องทดสอบในกลุ่มที่กำหนด
- ไม่มีการเปลี่ยนแพ็กเกจผู้ใช้จริง; admin มี Pro Max จึงใช้พิสูจน์ข้อจำกัด Free/Pro ไม่ได้
- การตั้งนัดเป็นปฏิทินภายในไมโล ไม่ได้อ้างว่าซิงก์ Google Calendar
- ต้องทดสอบแก้ข้อเสนอจากไฟล์ที่ส่งใหม่ก่อนยืนยัน; ไม่ใส่ข้อเสนอปลอมแทรกในคิว LINE ของผู้ใช้
- การเก็บไฟล์ไม่มีวันหมดอายุไม่สามารถพิสูจน์ด้วย seed ครั้งเดียว ต้องมีนโยบาย retention/backup และ recovery test

## รันซ้ำ

`node scripts/seed-uat.mjs` สร้างไฟล์ตัวอย่างและแสดง preview โดยไม่เขียนฐานข้อมูล

`node scripts/seed-uat.mjs --apply` เพิ่มแบบ transaction ครั้งเดียว โดยตรวจผู้ดูแลที่ผูก LINE ว่ามีคนเดียว และตรวจ audit batch ก่อนเพิ่ม ข้อผิดพลาดจะ rollback ทุกตาราง ไม่มีคำสั่งลบหรือแก้ยอดบัญชีเดิม

ไม่ควรเปลี่ยน batch แล้วรันเพื่อรีเซ็ต เพราะจะสร้างข้อมูลอีกชุด ให้ใช้บัญชี UAT ที่มีอยู่หรือออกแบบ cleanup ที่ตรวจขอบเขตก่อนต่างหาก
