# QA: สมุดบัญชีส่วนตัวและกลุ่ม LINE

วันที่ตรวจ: 27 สิงหาคม 2569

## ขอบเขตที่ตรวจ

| รายการ | ผล |
|---|---|
| Backfill ธุรกรรมเดิม | ผ่าน: พบ 11 รายการ ย้ายเข้า personal ledger ครบ 11 รายการ และไม่มีรายการที่ `financeAccountId` ว่าง |
| การเลือกสมุดบัญชี | ผ่าน: dashboard มีตัวเลือกบน desktop และมีแถบเลือกเต็มความกว้างบน mobile |
| การแยกขอบเขตข้อมูล | ผ่าน: API รายงาน รายการ งบ หมวด ยอดเริ่มต้น รายการประจำ และ AI รับ `financeAccountId` หลังตรวจสมาชิก |
| สิทธิ์สมาชิก | ผ่าน: viewer เพิ่มรายการไม่ได้; contributor เพิ่มได้; manager เปลี่ยนสมาชิกไม่ได้; owner เพิ่มสมาชิกได้เมื่อพบในกลุ่ม LINE เดียวกัน |

| Regression | ผ่าน: TypeScript, Vitest 92 กรณี และ production build |

## การใช้งานที่ตั้งใจ

บัญชีส่วนตัวเป็นค่าเริ่มต้นและไม่แชร์กับกลุ่ม กลุ่ม LINE จะเริ่มใช้สมุดบัญชีร่วมได้เมื่อเจ้าของเปิดบัญชีจาก dashboard เลือกกลุ่มที่ไมโลพบแล้ว และเพิ่มสมาชิกที่ไมโลเคยตรวจพบในกลุ่มนั้น บันทึกด้วยเสียงหรือใบเสร็จยังต้องยืนยันอย่างชัดเจนก่อนสร้างธุรกรรมเหมือนเดิม

## QA: ค้นหาธุรกรรมย้อนหลัง

ช่องค้นหากรองรายการจริงตามประเภท จำนวนเงิน หมวด และหมายเหตุ ภายในสมุดบัญชีที่กำลังเลือก และรีเซ็ต pagination เมื่อคำค้นหรือสมุดบัญชีเปลี่ยน Regression ของ helper ครอบคลุมคำค้นภาษาไทย จำนวนเงิน คำค้นว่าง และคำค้นที่ไม่พบข้อมูล เมนู “รายการธุรกรรม” ได้รับ regression เพิ่มเพื่อยืนยันว่าชี้ไปยัง workflow ค้นหาและตารางหลักฐาน โดยไม่มีการสร้างหรือแก้ไขธุรกรรม Screenshot ของ preview ยืนยัน dashboard โหลดปกติ แต่เครื่องมือภาพเริ่มจับจากส่วนบนแม้ระบุ fragment จึงยืนยัน behavior ของส่วนล่างด้วย TypeScript และ regression test แทน

## QA: เปรียบเทียบช่วงก่อนหน้า

dashboard สรุปรายรับ รายจ่าย และคงเหลือของช่วงที่เลือกเทียบกับช่วงก่อนหน้า โดยไม่แสดงเปอร์เซ็นต์สมมติเมื่อฐานของช่วงก่อนหน้าเป็นศูนย์ การตรวจ desktop และ mobile แสดงแผงสรุปต่อเนื่องในลำดับรายงานเดิม ส่วน logic ครอบคลุมวัน สัปดาห์ เดือน และปี พร้อมส่วนต่างแบบตัวเลขและร้อยละเมื่อคำนวณได้ การตรวจ TypeScript, Vitest 101 กรณี และ production build ผ่าน

## QA: โหลด Excel เมื่อจำเป็น

ตรวจ production build แล้ว `xlsx` ถูกแยกเป็น chunk สำหรับการส่งออกโดยเฉพาะ หน้า dashboard ไม่ต้องดาวน์โหลดไลบรารีดังกล่าวก่อนผู้ใช้กดปุ่ม Excel และยังผ่านชุด regression 103 กรณี

## QA: หลักฐานในตารางธุรกรรมหลัก

ตารางเดียวแสดงวัน รายการ หมวด จำนวนเงิน หลักฐาน และปุ่มจัดการต่อธุรกรรม โดยหลักฐานที่พบจะแสดงเป็นปุ่มเปิดไฟล์ และแถวที่ไม่มีหลักฐานจะแสดงสถานะ “ไม่มี” การตรวจ desktop และ mobile ยืนยัน layout ต่อเนื่องตามขนาดจอ Regression ของ cell mapper ครอบคลุมการจับคู่ระหว่างธุรกรรมสองรายการและกรณีแถวไม่มีไฟล์แนบ ส่วน regression สิทธิ์ยืนยันว่าผู้ไม่มี membership จะไม่เรียก query หลักฐาน

## QA: ค้นหาคลังใน workflow หลัก

แผงจัดการคลังรองรับการค้นหาชื่อไฟล์ แท็ก และลิงก์จากรายการจริงก่อนผู้ใช้กด “จัดการ” เพื่อเปิด dialog แก้ metadata ผลลัพธ์ว่างมีข้อความที่ชัดเจน และ regression ครอบคลุมคำค้นจากแท็ก/ลิงก์/ไม่พบข้อมูล การตรวจ desktop และ mobile แสดงแผงอย่างต่อเนื่อง พร้อมผ่าน TypeScript, Vitest 104 กรณี และ production build

## QA: สถานะและสิทธิ์หน้า settings

ยอดเริ่มต้น หมวด งบ และรายการประจำมี loading, error พร้อมปุ่มลองใหม่, และ empty state จาก query จริง การทดสอบสิทธิ์ยืนยันว่า `owner` และ `manager` เท่านั้นที่ทำให้ฟอร์มแก้ไขเปิดได้ ขณะที่ `contributor` และ `viewer` ถูกปิดการแก้ไข โดย backend ยังคงตรวจสิทธิ์ซ้ำ การตรวจล่าสุดผ่าน TypeScript, Vitest 105 กรณี และ production build

## QA: สถานะข้อมูลหน้าแอดมิน

แผงผู้ใช้และ audit log แสดง loading, error พร้อมปุ่มลองใหม่ และ empty state ที่ชัดเจนโดยไม่ซ่อนสถานะ query เมื่อข้อมูลไม่พร้อม ภาพ desktop และ mobile ยืนยัน layout ของหน้าแอดมินยังต่อเนื่องกับ dashboard ปัจจุบัน การตรวจ TypeScript, Vitest 105 กรณี และ production build ผ่าน

## ข้อค้นพบจากการตรวจ visual

การจัดวาง desktop อ่านง่าย ใช้สีเขียวมิ้นท์และระยะห่างสม่ำเสมอ แต่หน้ามีความยาวและ card หลายชนิดมีน้ำหนักใกล้เคียงกัน การเก็บงานรอบสุดท้ายจึงควรเน้นยอดคงเหลือ รายรับ รายจ่าย และธุรกรรมล่าสุดให้เด่นก่อนเครื่องมือจัดการรองลงมา โดยคงภาษาไทยสั้น กระชับ และน้ำเสียงแบบผู้ช่วยการเงินใน LINE

หลังปรับแล้ว dashboard วางยอดคงเหลือ รายรับ รายจ่าย และจำนวนธุรกรรม 7 วันไว้ในแถวแรก โดยเน้นยอดคงเหลือด้วยการ์ดโทนม่วงอ่อนและตัวเลขใหญ่ขึ้น การตรวจ screenshot ที่ 1280×720 และ 375×812 ยืนยันว่าข้อมูลยังเรียงอ่านง่ายในทั้ง desktop และ mobile
