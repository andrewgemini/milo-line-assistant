# Feature Matrix: การเงินไมโลตามภาพอ้างอิง

เอกสารนี้ใช้เป็นลำดับการพัฒนาระบบจัดการการเงินบนเว็บและ LINE โดยตรวจเฉพาะความสามารถที่มีในโค้ดและการทดสอบปัจจุบัน ไม่สร้างธุรกรรมตัวอย่างหรือยอดจำลองในหน้าผู้ใช้

| ฟังก์ชันจากภาพอ้างอิง | สถานะในไมโล | ขอบเขตที่ตรวจพบ | งานถัดไป |
|---|---|---|---|
| จดด้วยรูปและเสียง | มีแล้ว | OCR สลิป/ใบเสร็จ, ถอดเสียง, ข้อเสนอและยืนยันก่อนบันทึก | ตรวจ UX และเชื่อมหลักฐานเข้ากับธุรกรรม |
| ตั้งงบเริ่มต้น/งบรายวัน | มีบางส่วน | ตั้งงบต่อหมวดได้ผ่าน LINE และ dashboard | เพิ่มยอดตั้งต้นและหน้าจัดการงบมาตรฐาน |
| ส่งออก Excel/CSV | มีแล้ว | dashboard ส่งออกธุรกรรมและสรุปจากข้อมูลจริง | เพิ่มรายงาน PDF ที่อ่านง่าย |
| รายงานประจำเดือน | มีแล้ว | รายงานวัน/สัปดาห์/เดือน/ปี และ Flex card ใน LINE | ปรับส่วนควบคุมและตัวกรองจำนวนมาก |
| กราฟวิเคราะห์ | มีแล้ว | trend หมวดรายจ่าย การเลือกรายงาน และเปรียบเทียบช่วงก่อนหน้าจากข้อมูลจริง | เก็บ QA ตามข้อมูลจริง |
| ตั้งออโต้รายการจำนวนมาก | ยังไม่มี | มีสรุปการเงินอัตโนมัติและ reminder แต่ไม่มี recurring transaction | เพิ่ม recurring transaction พร้อมยืนยันก่อนรอบแรก |
| ใบเสร็จ/ไฟล์แนบ PDF | มีแล้ว | ไฟล์เก็บใน S3 vault, OCR รูป, ความสัมพันธ์กับธุรกรรม และหน้าเปิดหลักฐานตามสิทธิ์ | เก็บ QA ตามข้อมูลจริง |
| จดในกลุ่ม/หลายบัญชี | มีบางส่วน | แยกกลุ่ม LINE และ RBAC ได้ | เพิ่มตัวเลือก context/account ใน dashboard พร้อม isolation |
| ระบบจัดการมาตรฐานบนเว็บ | มีแล้ว | dashboard มีธุรกรรม, รายงาน, ผู้ใช้, role, audit, หมวด, งบ, รายการประจำ และ pagination | เก็บ QA ของ workflow ตามข้อมูลจริง |

> ลำดับการทำงานคือปิดช่องว่างด้านข้อมูลก่อน แล้วจึงเพิ่มหน้าจัดการและการส่งออก เพื่อหลีกเลี่ยงการแสดงข้อมูลสังเคราะห์หรือการปะปนระหว่างบัญชี/กลุ่ม

## ความคืบหน้า: การบันทึกและหมวดบัญชี

ตาราง `expense_categories` รองรับ `transactionType` แล้ว โดยข้อมูลเดิมถูกคงไว้เป็น `expense` และ unique key ใหม่อนุญาตให้ชื่อหมวดเดียวกันอยู่คนละประเภทธุรกรรมได้ ผู้ใช้จึงจัดการหมวดรายรับและรายจ่ายแยกกันผ่าน LINE เช่น `เพิ่มหมวดรายรับ โบนัส`, `ลบหมวดรายรับ โบนัส`, `ดูหมวดรายรับ` และสามารถใช้ API ที่มีสิทธิ์ผู้ใช้เพื่อจัดการหมวดจาก dashboard ในขั้นตอนถัดไป การสร้างหรือลบหมวดจากเว็บจะบันทึก audit log

การตรวจ TypeScript, Vitest 80 กรณี และ production build ผ่าน โดยมี regression สำหรับคำสั่งภาษาไทยและการคง compatibility ของคำสั่ง `เพิ่มหมวด เดินทาง` เดิม

## ความคืบหน้า: ยอดตั้งต้นและรายการอัตโนมัติ

เพิ่มยอดเงินตั้งต้นเป็นข้อมูลแยกต่างหากจากธุรกรรม โดยคำสั่ง LINE `ตั้งยอดเงินเริ่มต้น 5000 บาท` และ API บนเว็บจะเก็บวันที่มีผลและบันทึก audit ยอดคงเหลือที่ใช้งานได้คำนวณจาก **ยอดตั้งต้น + รายรับ − รายจ่าย** โดยไม่เปลี่ยนยอดกำไร/ขาดทุนในรายงานเดิม

เพิ่มกฎรายการอัตโนมัติรายวัน รายสัปดาห์ และรายเดือน พร้อมตาราง run record ที่มี unique key เพื่อกัน Heartbeat สร้างธุรกรรมซ้ำเมื่อ callback ถูกเรียกซ้ำ งานที่ถึงเวลาเท่านั้นจึงสร้างธุรกรรมจริง พร้อมเก็บ source เป็น `recurring` และ audit โดยยังไม่ได้สร้างกฎหรือธุรกรรมตัวอย่างในบัญชีผู้ใช้ การตรวจ TypeScript, Vitest 85 กรณี และ production build ผ่าน

## ความคืบหน้า: รายงานและการส่งออก

dashboard มี CSV และ Excel จากธุรกรรมจริงอยู่แล้ว จึงเพิ่มปุ่ม PDF ที่เปิดหน้าต่างพิมพ์พร้อม layout A4 ธีม `MILO • FINANCE` ให้ผู้ใช้เลือก Save as PDF จาก browser รายงานประกอบด้วยรายรับ รายจ่าย กำไร/ขาดทุน รายจ่ายตามหมวด และตารางธุรกรรมที่ส่งเข้ามาจริง ไม่มีการเติมรายการตัวอย่าง การสร้าง HTML escape ข้อความธุรกรรมก่อนแสดงเพื่อป้องกันการแทรก markup การตรวจ TypeScript, Vitest 86 กรณี, production build และ screenshot dashboard ผ่าน

## ความคืบหน้า: หลักฐานใบเสร็จและไฟล์แนบ

เพิ่ม `transaction_attachments` เพื่อเชื่อมธุรกรรมกับ `vault_items` โดยเก็บเพียงความสัมพันธ์และ metadata ไม่คัดลอก byte ของไฟล์จาก S3 ใบเสร็จหรือสลิปจะถูกเชื่อมเป็นหลักฐานหลังผู้ใช้ **ยืนยันค่าใช้จ่าย** เท่านั้น และไฟล์เสียงจะถูกเชื่อมเมื่อผู้ใช้ยืนยันข้อเสนอธุรกรรมเสียง การเชื่อมตรวจสิทธิ์เจ้าของของทั้งธุรกรรมและไฟล์ก่อนบันทึก พร้อม audit log การตรวจ TypeScript และ Vitest 86 กรณีผ่าน

## ความคืบหน้า: กลุ่ม LINE หลายบัญชี และสิทธิ์ระดับบัญชี

เพิ่มสมุดบัญชี (`finance_accounts`) แยก **บัญชีส่วนตัว** และ **บัญชีกลุ่ม** พร้อมตารางสมาชิก (`finance_account_members`) ที่มีบทบาท `owner`, `manager`, `contributor`, และ `viewer` ธุรกรรม งบ หมวด ยอดเริ่มต้น รายการประจำ รายงาน กราฟ AI และ export ใช้รหัสสมุดบัญชีเป็นขอบเขตข้อมูล บัญชีส่วนตัวเดิมยังทำงานได้โดยไม่ต้องเลือกบัญชีใหม่

การเปิดบัญชีกลุ่มต้องอาศัยกลุ่ม LINE ที่ไมโลตรวจพบและยืนยันว่าผู้เปิดเป็นสมาชิกแล้ว การมอบบทบาททำได้เฉพาะเจ้าของ และสมาชิกที่จะเพิ่มต้องถูกตรวจพบในกลุ่มเดียวกันก่อน จึงไม่มีการแชร์ข้อมูลส่วนตัวกับกลุ่มโดยอัตโนมัติ `viewer` อ่านได้เท่านั้น, `contributor` เพิ่มรายการได้, `manager` จัดการรายการและการตั้งค่าได้, และ `owner` จัดการสมาชิกได้เพิ่มจากสิทธิ์ทั้งหมดข้างต้น

migration 0011 backfill ข้อมูลจริงเดิมแบบไม่สร้างธุรกรรมใหม่ โดยพบธุรกรรมเดิม 11 รายการของผู้ใช้หนึ่งราย และย้ายครบทั้ง 11 รายการเข้าสมุดบัญชีส่วนบุคคลหนึ่งบัญชีโดยไม่มีรายการที่ไร้ขอบเขต การทดสอบ Vitest 92 กรณี รวมการปฏิเสธข้ามบัญชี/ผู้ดูและการมอบสิทธิ์สมาชิก และ production build ผ่าน

## ความคืบหน้า: หน้าจัดการเว็บมาตรฐาน

dashboard มีแผงตั้งค่าการเงินสำหรับยอดตั้งต้น หมวดกำหนดเอง งบรายเดือน และรายการรายรับ/รายจ่ายประจำ โดยทุกส่วนใช้สมุดบัญชีที่เลือกและปิดการแก้ไขทันทีเมื่อบทบาทเป็นผู้ดู เพิ่ม dialog และทางเข้าจัดการแท็ก/ลิงก์ของคลังแบบตรง มีปุ่มยกเลิก สถานะกำลังบันทึก และรักษาค่าที่มีอยู่หากผู้ใช้ไม่ได้แก้ไข

ตรวจ visual regression ทั้ง desktop และ mobile แล้ว หน้าจอคง layout พาสเทลเขียว–ฟ้า รองรับการเรียงแผงฟอร์มตามความกว้างจอ และไม่มีข้อมูลการเงินตัวอย่าง เมนูคลังชี้ไปยังแผงจัดการ metadata โดยตรง การตรวจ TypeScript, Vitest 94 กรณี และ production build ผ่าน โดยไม่พบ browser error ใหม่ใน log หลังเวลา 10:45 น.

ตารางธุรกรรมรองรับการแบ่งหน้าละ 20 รายการสำหรับสมุดบัญชีที่เลือก โดยคำนวณหน้าที่ใช้ได้อย่างปลอดภัยและรีเซ็ตสู่หน้าแรกเมื่อเปลี่ยนสมุดบัญชี รายการมีเพียง 11 รายการในบัญชีจริงปัจจุบันจึงยังไม่แสดงตัวควบคุม pagination แต่ regression ครอบคลุมกรณี 41 รายการและหน้าเกินขอบเขตโดยไม่สร้างหรือแก้ไขข้อมูลจริง การตรวจล่าสุดผ่าน TypeScript, Vitest 95 กรณี และ production build

ตารางจัดการธุรกรรมหลักแสดงวัน รายการ หมวด จำนวนเงิน การแก้ไข และใบเสร็จ/สลิป/ไฟล์เสียงที่ยืนยันแล้วในแถวเดียวกัน ปุ่มเปิดไฟล์ใช้เฉพาะ URL ของรายการในคลังที่เชื่อมแล้ว API query แบบ batch จำกัดสูงสุด 20 ธุรกรรมในหน้าปัจจุบันและตรวจสิทธิ์สมุดบัญชีก่อนอ่านข้อมูลทุกครั้ง ผู้ที่ไม่มี membership จะถูกปฏิเสธโดยไม่เรียก query หลักฐาน Regression ของ cell mapper ครอบคลุมแถวที่มีหลักฐานต่างรายการและแถวที่ไม่มีหลักฐาน การตรวจ TypeScript, Vitest 103 กรณี, production build และ screenshot desktop/mobile ผ่าน

dashboard เพิ่มการค้นหาธุรกรรมย้อนหลังจาก **ประเภท จำนวนเงิน หมวด และหมายเหตุ** เฉพาะข้อมูลในสมุดบัญชีที่เลือก คำค้นและการสลับบัญชีจะพากลับหน้าแรกของผลลัพธ์เพื่อไม่ให้เกิดหน้าว่าง เมนูรายการธุรกรรมเลื่อนไปยัง workflow ค้นหาและตารางหลักฐานโดยตรง การตรวจล่าสุดผ่าน TypeScript, Vitest 99 กรณี และ production build โดยไม่สร้างหรือแก้ไขข้อมูลการเงินจริง

คลังมีช่องค้นหาภายในแผงจัดการ metadata หลัก รองรับชื่อไฟล์ แท็ก และลิงก์ โดยผลลัพธ์ทั้งหมดเป็นรายการจริงจาก vault และเปิด dialog เพื่อแก้ metadata เท่านั้น การตรวจ TypeScript, Vitest 104 กรณี, production build และ screenshot desktop/mobile ผ่าน

หน้าจัดการมาตรฐานรวบรวมยอดเริ่มต้น หมวด งบ และรายการประจำไว้ตามสมุดบัญชีที่เลือก พร้อม loading/error/retry/empty/read-only states และตรวจ role ฝั่ง client เพิ่มเติมก่อนเปิดฟอร์มแก้ไข การตรวจล่าสุดผ่าน TypeScript, Vitest 105 กรณี และ production build

หน้า dashboard และ Excel export ถูกแยกโหลดแล้ว โดยไลบรารี `xlsx` จะดาวน์โหลดเฉพาะเมื่อผู้ใช้กดสร้างไฟล์ Excel จากธุรกรรมจริง ขนาด dashboard ที่โหลดเริ่มต้นลดจากประมาณ 1.03 MB เหลือ 741 KB (gzip 170 KB) ส่วน Excel แยกเป็น chunk 429 KB (gzip 143 KB) การตรวจ TypeScript, Vitest 101 กรณี และ production build ผ่าน
